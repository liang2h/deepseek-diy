# 下一轮输入建议

独立的 DSH 插件 `@local/dsh-next-input`，适配已核验的 **DSH 0.2.2-rc.3**。

## 使用

会话一轮正常结束且输入框为空时，插件自动检查最近的用户输入和助手回答。明确的“未确认事项、证据尚未取得、仍不能下结论”，以及已有完成证据但后续步骤明确尚未执行/延期的结果（如代码已推送、尚未创建发布标签），会优先生成安全的本地下一步准备建议；其他情况由模型判断是否仍有任务缺口，并在输入框上方显示一条 **下一轮建议**。本轮待办已完成不等于整个工作流已经闭合；“本轮不执行”也不表示不能推荐下一轮先检查和确认。

- 点击建议：只填入空白草稿，随后可编辑，**不会发送**。
- 点击关闭：忽略本轮建议。
- 已有文字（含空格）、附件、发送中、运行中的会话、子智能体会话均不显示建议；不会覆盖草稿。
- 没有明确缺口：不显示建议，原输入框和背景文案保持原样。
- 模型返回无效结果、调用失败或超时：仅显示可关闭的“本轮建议暂不可用”提示，不改草稿，不把失败伪装成“没有缺口”。
- 新一轮开始后旧建议失效；切换会话不会把旧结果填到新会话。

**为什么不是直接替换背景文案？** 当前版本没有公开的占位文案扩展接口。本插件使用原生的附加槽位 `conversation.input.dock`，不替换输入框、不改 DSH 安装目录、不读写其他插件的 DOM，不接管 Enter/Tab 等快捷键。

## 数据与费用

明确的未确认章节及已延期后续操作优先使用本地规则生成证据清单、验证计划或下一阶段预检建议，不发起额外模型请求；权限受阻时只建议准备所需证据与权限申请，不代表授权或继续访问。其他情况使用刚结束一轮的模型路由，对限量的最近对话文本发起额外的辅助请求，可能产生模型服务费用。不会运行工具、发送用户消息、唤醒目标或创建新会话。默认采用该模型支持的较低思考强度；不保证一定无思考开销。

本地规则和模型判断都不是确定性的任务验收：有限历史、文本截断以及未读取图片或附件，均可能导致遗漏或误判。不会把工具结果或系统指令发送给辅助模型。建议缓存仅驻留内存，重启后可能对当前已完成轮重新判断；没有完整的请求重放/审计记录。

关闭插件即停止新增建议，已经点击填入的草稿继续由 DSH 原输入框保存。

## 安装

在 DSH **插件 → 添加插件** 中选择本目录。也可以要求智能体用原生 `plugin_manager` 安装该目录。安装影响当前 profile 的所有会话；以安装器返回的应用状态为准，若提示重启则重启。

包内包含构建完成的客户端文件，安装无需运行生命周期构建脚本。源码链接安装后修改代码，不等于浏览器已收到更新；根据 DSH 的重新加载/重启提示操作。

## 开发与测试

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm build
pnpm test
```

Node.js 24+，pnpm 11.28.5。客户端使用 DSH 自带的 React 实例，不另外打包 React。开发构建依赖 esbuild；运行依赖 zod、schemastery。发布渠道为 [plugins-v1.2.0](https://github.com/liang2h/deepseek-diy/releases/tag/plugins-v1.2.0)；对应工作流成功后，可下载安装包或从[插件索引](https://liang2h.github.io/deepseek-diy/index.json)安装。

测试覆盖纯投影、上下文截断、保守解析、单轮去重、调用结束状态、取消/过期结果、并发上限、空草稿与附件/编辑竞争保护。默认 `pnpm test` 还会在普通 Node.js 24 / Linux runner 上执行三项 npm 契约测试，**不因缺少 Desktop 或环境变量而跳过**：

- Gateway Client：真实 Cordis/Typert/Gateway 的作用域身份绑定、`RemoteResult` 封包解析、有建议/无缺口的展示选择及失败分支。
- Gateway Host：真实严格注册、参数校验、身份查找和 Host → Client → 展示选择器链路；保留未知字段、无效请求、缺失身份的拒绝断言。
- Inspect schema：调用 SDK 导出的原生 `assertSupportedJsonSchema` / `validateJsonSchemaValue` 校验 Host/Client 声明、输入和输出，并验证不支持的 schema 关键词仍被拒绝。

依赖来自 public npm：四个直接 DSH SDK 开发依赖精确固定为 `0.2.2-rc.3`，Cordis 为 `4.1.0`；锁文件固定传递依赖和完整性摘要。测试递归检查所有可达 DSH 依赖/peer 均为该 rc.3，且共享同一 Cordis 模块，Client 使用已发布的 Node export。缺失或版本/来源不一致会失败，不回退到全局包或 Desktop。测试子进程使用当前 `process.execPath`，清除继承的 `DSH_*`、`NODE_PATH` 和 `ELECTRON_RUN_AS_NODE`；不需要 `DSH_NODE_EXECUTABLE` 或 `DSH_INSTALL_DIR`。

仅连接既有的 fixture Agent/Session、内存 RPC 与固定模型响应；Gateway 与原生 schema 校验器不做 mock，不打开 socket/浏览器、不读个人会话或 profile、不调用生产模型。以上是 **npm SDK 隔离契约测试，不是 GUI 或真实 Desktop 安装验收**。

不把槽位注册成功或隔离集成测试等同于真实页面验收；没有浏览器控制时，仍需人工检查明暗主题、真实模型判断及点击流程。

## 1.0.5 诊断兼容

- 修复 Inspect 声明使用当前 DSH 不支持的 `minLength/maxLength` 导致诊断注册失败的问题；会话身份长度改在处理器内校验。
- 回归使用固定 DSH `0.2.2-rc.3` npm SDK 的原生 schema 校验器，验证 Host/Client 的声明、输入和返回值。推荐策略与投影版本（4）不变。

## 1.0.4 下一阶段操作

- 不再只识别“未确认事实”：已有阶段完成证据，但明确尚未执行或延期的下游操作，也可形成下一轮输入。例如“代码已提交并推送、测试通过，但未创建发布标签”，会优先提示下一次发布的预检清单和待确认事项。
- “本次/本轮不打标签”仍约束本轮执行，推荐不会创建标签或替代授权；全局禁止发布、明确不需要后续建议、已经完成后续阶段时，不制造该步骤。
- 本地规则覆盖明确的发布/部署/合并接续，其余场景使用 v3 语义提示判断。闭合任务、示例和引用不应触发。投影版本为 4，升级后重建旧判定。
- `NextInput.status` 可选 `sessionId`：Host 只查看已驻留 Agent，Client 只读已挂载视图的标志；不会为了诊断恢复历史会话、触发模型或返回正文。

## 1.0.3 未确认事项与诊断

- 明确的“仍不能下定论 / 未确认项 / 待验证”章节只要包含具体未解决事实，就优先显示本地准备建议；不会因待办已完成、原验收未写明进一步验证或辅助模型返回空而消失。
- 审批/权限受阻时只生成证据清单和权限申请准备输入，不继续查询，不视为用户授权；用户明确要求停止、仅总结、不跟进时仍保持安静。
- 长会话压缩移除首条任务摘录后，最新完整回答中的明确未确认项仍可触发安全的计划类提示；旧的被替换文本仍会失效。投影版本为 3。
- 在提供 Inspect 的环境下，Host/Client 都可只读查询 `NextInput.status`，核对**实际加载代码**的版本、触发状态、草稿/附件是否阻挡、缓存结果或失败原因；不返回对话正文、草稿、标题或凭据，不触发模型。查询作用域是发起 Inspect 的会话，不一定是页面当前选择的会话。

## 1.0.2 交互样式

- 建议卡片与失败提示统一沿用原输入框的宽度轴与两侧留白，随内容宽度调整和窄屏变化，不再横跨整页。
- 失败提示改为低干扰的信息卡片，信息图标、提示文字与关闭按钮集中在同一行，长文案可换行。
- 统一间距、圆角、悬停/键盘焦点反馈；触屏关闭区域为 40×40，并支持减少动态效果偏好。关闭提示仍仅回到当前会话输入框，不改草稿。
- 此版本只调整客户端展示，不更改生成策略和模型调用参数。

## 1.0.1 修复

- 修复前端误把 `{ok, value}` 远程结果封包当成建议正文，导致成功响应也不显示的问题。
- 修复借用会话上下文直接读取 `remote` 的依赖权限问题，改为通过公开 `get()` 获取带会话身份的命名空间。
- 正常的系统提示单节点替换不再误清用户任务；真正触及已保留文本的替换仍会让旧建议失效。投影版本升至 2，以丢弃旧折叠缓存并重建。
- 请求失败与“判断无缺口”分开处理；前者显示可关闭提示，后者保持安静。升级已加载的插件后，以安装器的激活结果为准；若要求重启，必须重启 DSH，单纯刷新页面不能替换旧 Host 模块。
