# Git 工作台 · Git Workbench

当前 DSH Web GUI 内的 SourceTree 风格 Git 管理插件。原生 React 标签页，不使用 iframe、外部网站或独立服务器。

## 打开

- 仅保留右侧栏 **开始 → Git 工作台** 入口（可通过右侧栏的 **＋** 打开开始页）。
- 不注册会话顶部 Git 按钮，也不注册 `/git-workbench` 斜杠命令。
- 默认使用当前 DSH 会话目录，可输入仓库绝对路径或使用“选择仓库”。

## 已实现

- 文件状态：已暂存/工作区分组、文件筛选、单文件和批量暂存/取消暂存。
- 差异：工作区、暂存区、未跟踪文本和历史提交；统一差异视图、增删着色、行号。
- 提交：UI 填写说明并确认后提交暂存内容；Agent 按用户要求执行本地 `commit` 时不再增加插件额外审批。可显式指定 `paths`，先暂存这些路径再提交全部已暂存内容；支持尚无初始提交的仓库。
- 提交历史：拓扑提交图、作者、日期、引用、分页和提交差异。
- 分支：本地/远程分支、创建、切换、安全删除、合并到当前分支。
- 同步：按远端获取；已配置上游分支的仅快进拉取和普通推送；领先/落后计数。
- 储藏：储藏已跟踪文件的更改，列出储藏，应用最新储藏。
- 初始化：只允许显式指定已经存在的空目录，不会自动初始化当前目录。
- 中英文 UI 和插件元数据；沿用 DSH 主题色。
- UI 与 Agent 工具 `git_workbench` 共用同一个 Host 服务实现。UI 通过 DSH Connection 的认证精确路由 `/api/local-git-workbench/execute` 调用，保留 Host/Origin 校验、浏览器身份认证、会话解析、取消和写操作确认，不向斜杠菜单暴露内部接口。此通道不生成会话斜杠命令日志，错误仍由工作台直接展示。

## 安全边界

每次 UI 写操作仍先显示仓库、操作和参数，确认后执行。Agent 仅在用户要求提交时使用 `commit`；本地 `commit`（有无 `paths` 均包括）不再调用插件自己的 `approval.request()`，不会出现旧版本「一次确认：暂存指定路径后提交」弹窗。需要暂存后提交时，优先在 `commit` 中指定 `paths` 与 `message`，而不是拆成独立 `stage` 调用。

独立 `stage`／`unstage`、push、pull、fetch、merge、分支操作、stash 等其它写动作仍保留原有业务审批；仅 `allowed-once` 才执行。该变化不是缓存或复用历史批准，也不接受模型用 `confirmed:true`、自动授权参数或提交提示词为其它动作放行。

组合提交仍会包含**原先已经暂存的全部更改**，并非只提交 `paths`。省略 `paths` 则不执行暂存，只提交当前暂存区。所有参数仍在执行前校验，非法请求不执行 Git；非提交动作被拒绝时也不会执行 Git。指定路径会按当前工作区状态重新暂存，可能替换这些路径原有的部分暂存内容。暂存与提交属于同一服务队列操作，但不是可自动回滚的事务：若暂存成功后提交失败或取消，暂存区可能已改变，应先检查状态；不会为了恢复而自动 reset、回滚、重试或进一步覆盖暂存区。

平台工具策略、沙箱限制、取消与提交准备 guard 继续生效。本插件没有关闭全局审批、安装自动批准器或修改 Session approval policy；因此不保证平台其它独立安全策略永远不再询问。Git hooks 仍在原沙箱下执行。

**旧审批卡不会被追认或自动点击允许。** 更新仅影响新调用；若旧请求仍等待审批，请拒绝／取消该请求，确认更新生效后重新发起提交。更新若因卸载旧插件取消了旧请求，同样应重新发起，不应把未知执行结果直接重试。

所有 Git 调用均使用参数数组和 DSH subprocess 服务，不拼接 shell；读操作使用只读沙箱，写操作遵守会话的文件沙箱。不自动重试放宽权限。管理会话工作区以外的仓库时，读取通常可用，但写入可能被拒绝：请在该仓库中打开 DSH 会话。Git 自身的钩子、过滤器及凭证配置仍受同一沙箱约束。

不提供强制推送、硬重置、丢弃文件、clean、强制删除分支或任意 Git/shell 命令。拉取固定 `--ff-only`，删除分支固定 `-d`。合并与应用储藏仍可能产生冲突，错误会原样展示，应在编辑器中解决并暂存。

## 限制

这是可用的首版 Git 工作台，不是 SourceTree 的全部功能：不含交互式 rebase、cherry-pick、逐 hunk 暂存、标签管理、克隆和远端编辑。远端需先通过 Git 配置；推送/拉取需要已有上游。无密码输入框，复用本机 Git 凭证/SSH 配置，不能交互认证时会报错。储藏不包含未跟踪文件。

历史分页，差异输出有上限；二进制文件只显示 Git 的提示。点击刷新或执行操作后刷新状态，不轮询文件系统。仓库选择保留在当前标签生命周期中，页面重新载入后回到会话目录。

## 开发与验证

无安装脚本、无额外运行依赖。`node --check index.js`、`node --check git.js`、`node --check client.js`；运行 `node --test test/*.test.js`。

使用 DSH 的 `plugin_manager install_bundle` 安装本目录。该安装会作用于当前 profile 的所有会话，并在重启后保留。不要手工修改 profile 配置。首次安装可热激活；升级已安装模块通常需要重启 DSH，不能把源码修改当作已运行的新版本。

- 本地提交仍需符合 Session 权限及配置的提示词准备检查；不会自动提交、推送或替用户批准旧请求。

## 历史行为（v1.0.4：曾保留一次提交审批）

- `status` 是 `summary` 的只读兼容别名，工具与 UI RPC 都接受；读取状态不申请审批。
- Agent 示例：`git_workbench({action:"commit",paths:["src/file.ts"],message:"fix: 修复说明"})`。需要查看未暂存变更时，应先读取对应差异；配置的 Git 提示词准备步骤仍需在生成提交说明前完成。
- `paths` 只能为 1–200 个显式仓库相对字面路径；`["."]` 明确表示所有文件，不会隐式默认全部暂存。处理重命名时复用原有暂存逻辑。
- 没有新增免审批设置、模型授权参数、长期授权缓存或 shell 执行入口；原有手工 UI 仍按用户点击分别确认各操作。
- 50 项 Git 引擎／Host／Client 契约测试全部通过，覆盖只读别名、一次调用一次审批、拒绝零写入、非法参数审批前拒绝、组合提交的选定范围、既有暂存、失败及取消；Git 提示词插件的 102 项测试和安装版隔离工具管线验证也通过。真实写操作仅在带所有权标记和路径校验的临时测试仓库执行；审批服务／沙箱使用测试替身，不冒充实际审批 UI 或 OS 隔离验收。
